# Research / knowledge package

This directory holds the machine-readable knowledge package generated by
`tools/build_knowledge.py`.  It is the compact, schema-versioned, CRC-protected
encoding of the protocol knowledge used to reason about observed USB-PD
traffic on the STM32H7R3Z8J6 sink.

## Files

| File | Purpose |
| --- | --- |
| `usb_pd_knowledge.json` | Human/machine-readable knowledge document |
| `pd_knowledge.bin` | Compact firmware-importable blob (magic `KPD1`, schema v1) |
| `pd_knowledge.h` | C header embedding the blob (import-ready) |

## Blob sections (schema v1)

| Tag | Content |
| --- | --- |
| `MSGS` | control-message table (type → name) |
| `MSGD` | data-message table |
| `MSGE` | extended-message table |
| `SVDM` | structured-VDM command table |
| `SOPN` | SOP / SOP' / SOP'' names |
| `PDOM` | PDO/APDO field metadata (bit positions, steps) |
| `CAPS` | safety guard rails + hardware capability gates |
| `QURY` | schedulable-query catalogue |
| `MODL` | model metadata (id/version/feature/accuracy) |
| `OBSV` | vendor observations (e.g. PB722), observation-only |
| `TRAN` | charging-protocol **transport** table |
| `PKSC` | compact packet schemas (header bits, payload, response) |
| `SCAL` | scalar/units notes (log2 table, entropy scale, confidence) |

## Charging-transport research (section I) — summary

Every charging family is recorded with its **actual physical/electrical
transport**.  Crucially, only USB-PD and USB-C CC signalling are observable
through the UCPD connector on this board:

| Charging system | Transport | Observable via UCPD? |
| --- | --- | --- |
| USB-PD / PPS / EPR / VDM | USB-C CC | **Yes** |
| USB-C Rp / default current | USB-C CC | **Yes** |
| BC1.2, QC, AFC, Huawei SCP/FCP, VOOC/SUPERVOOC, Vivo, Xiaomi proprietary | D+/D- (or proprietary VBUS signalling) | **No** (D+/D- not wired) |

The firmware therefore makes **no** D+/D- / non-PD charging compatibility
claim.  These entries exist so the research knowledge is complete and correct,
and so a future external D+/D- analyzer architecture has the transport facts
recorded.  Proprietary D+/D- protocols are never mis-classified as USB-PD.

## Packet schemas (section J)

`PKSC` stores compact packet schemas: message name, protocol, SOP, message
type, kind (control/data/extended/vdm), number-of-objects, header bit ranges,
payload layout, and expected response.  `tools/apie_replay.py --mode=synthetic`
generates a synthetic session and `tools/apie_replay.py` validates every packet
against these schemas.

## Regenerate

```sh
python3 tools/build_knowledge.py            # generate all three files
python3 tools/build_knowledge.py --verify research/pd_knowledge.bin
```

The blob is deterministic (no timestamps/random data), so regeneration is
reproducible and CRC-stable.
